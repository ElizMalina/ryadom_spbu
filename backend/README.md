# Backend «Рядом»

Бэкенд реализует публичный каталог статей, локальные аккаунты, управление
ролями и проверку публикаций. Контракт описан в
[`../api/openapi.yaml`](../api/openapi.yaml).

## Запуск

```bash
cd backend
docker compose up --build
```

Сервер будет доступен по адресу `http://localhost:8080`, PostgreSQL — только
внутри Docker-сети. При первом запуске приложение само применит миграции из
`internal/data/` и добавит безопасные тестовые статьи, категории и теги.

Для запуска без Docker сначала поднимите локальный PostgreSQL, затем задайте
`DATABASE_URL` по примеру из `.env.example` и выполните:

```bash
cd backend
go run ./cmd
```

Публичные endpoint'ы:

- `GET /api/v1/psychoeducation/materials`
- `GET /api/v1/psychoeducation/materials/{slug}`
- `GET /api/v1/psychoeducation/filters`
- `GET /health`
- `GET /ready`

Приложение использует PostgreSQL-store на GORM. `memoryStore` оставлен только
для изолированных HTTP-тестов и не используется при запуске приложения.
GORM не применяет схему автоматически: изменения схемы выполняются только
версионируемыми SQL-миграциями из `internal/data/`.

## Локальные аккаунты и роли

- `GET /api/v1/auth/session` возвращает текущего пользователя или `null` для
  гостя. Вход выполняется через `POST`, выход через `DELETE` на том же маршруте.
- `GET /api/v1/users` показывает список аккаунтов администратору. `PATCH`
  заменяет роли указанного пользователя.
- `GET` и `POST /api/v1/wall` обслуживают стену «Накопилось». Очередь доступна
  через `GET /api/v1/wall?view=queue`, решение передаётся через `PATCH /api/v1/wall/{id}`.
- `GET` и `POST /api/v1/psychoeducation/articles` обслуживают собственные статьи,
  очередь и отправку на проверку. `PATCH` и `DELETE /api/v1/psychoeducation/articles/{id}`
  обслуживают проверку и действия автора.

Назначаются роли `student`, `consultant`, `psychologist`, `admin`, `moderator`
и `reviewer`. Гость не имеет сессии. Студент может отправить запись на стену,
а модератор проверяет её. Консультант может отправить, изменить или удалить
свою статью. Клинический рецензент проверяет статьи и может одобрять только
работы других авторов. После одобрения статья появляется в публичном каталоге.
Для решения достаточно передать `status`. Если клиент также передаёт `revision`
из очереди и версия уже изменилась, API вернёт `409 stale_revision`.
В этом случае обновите очередь и прочитайте новую версию статьи.

Вход использует существующую локальную учётную запись. Публичной регистрации
нет. Университетский SSO и запись к психологу согласуются отдельно.

### Первый администратор

Перед первым запуском можно задать обе переменные
`AUTH_BOOTSTRAP_ADMIN_USERNAME` и `AUTH_BOOTSTRAP_ADMIN_PASSWORD`. Выберите
новый логин и уникальный пароль длиной не меньше 12 символов и не больше
72 байт UTF-8. При запуске приложение выдаёт роль `admin` создаваемому
аккаунту. Если логин уже принадлежит обычному аккаунту, приложение сообщит
об ошибке запуска. Повторный запуск с логином созданного администратора не
меняет его пароль.

Для Docker Compose задайте переменные в локальном `backend/.env`.
Для `go run ./cmd` передайте их в окружении процесса. После успешного создания
аккаунта переменные начальной настройки можно убрать перед следующим запуском.
Файл `.env` и реальный пароль должны оставаться вне репозитория.

Сессия сохраняется в PostgreSQL и действует 8 часов. Cookie `ryadom_session`
использует атрибуты `HttpOnly`, `SameSite=Lax` и по умолчанию `Secure`.
Для локального запуска по HTTP задайте `AUTH_COOKIE_SECURE=false`.
На стенде с HTTPS оставьте `Secure` включённым.
