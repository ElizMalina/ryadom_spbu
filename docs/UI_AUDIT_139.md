# Issue #139 — Senior Frontend Review / адаптивность главной

PR: https://github.com/mshipilov5/Ryadom_spbu/pull/172

## Исправленные дефекты

1. **Critical UX / P1:** горизонтальное переполнение: `width: 100%` + `padding` без `border-box` внутри grid-колонки. Использованы `box-sizing: border-box`, `minmax(0,1fr)`, `min-width: 0`, перенос текста. `overflow-x: hidden` специально **не используется**: это скрывает симптом, а не исправляет геометрию.
2. **P1:** iPhone показывает обрезанное меню и кнопку экстренной помощи. Вместо горизонтального длинного списка — раскрывающееся меню с `aria-expanded`, полноценная кнопка «Нужна срочная помощь» и одноколоночные CTA.
3. **P1:** фон sidebar заканчивался на высоте viewport, хотя основной контент продолжался ниже. Фоновая `homeSidebarColumn` растягивается по высоте grid-контейнера; внутреннее меню закреплено (`position: sticky`) и прокручивается внутри при малой высоте окна.
4. **P2:** весь `page.tsx` требовал hydration из-за одного `useState`. Страница стала серверным компонентом, а меню и выбор настроения — отдельными маленькими клиентскими компонентами.
5. **P2:** отсутствовал независимый от других разделов `focus-visible`. Добавлен в CSS главной.
6. **P2:** неконкретные имена и массивы позиционных строк. Использованы типы `NavigationItem`, `HomeCard`, `Mood`, названные ключи объектов.
7. **P2:** smoke-тесты проверяли тексты и брейкпоинт, но не защищали от повторного overflow. Добавлены регрессионные проверки структуры CSS, поведения mobile-nav и семантики.

## Edge cases и безопасность

- В этом коде **нет сетевых запросов, подписок, таймеров или сторонних эффектов** — подтверждённых race condition и утечек памяти здесь нет.
- Нет `dangerouslySetInnerHTML`; React экранирует строковые значения. Никакие данные не отправляются на сервер.
- Навигация содержит ссылки на разделы, которые могут пока отсутствовать в `main` — это отдельная интеграционная зависимость, не дефект адаптивности.
- Поиск остаётся disabled-моком согласно issue #61.
- Root layout Next.js по умолчанию формирует viewport metadata; не отключать масштабирование жестами через `user-scalable=no`.

Дополнительно обязательно проверить **реальное** Next.js-приложение в Safari на iOS и Chrome/Firefox desktop при 100% масштабе; HTML-предпросмотр Chromium не заменяет это тестирование.

Контрольные размеры: 320, 360, 375, 390, 414, 430, 760, 768, 900, 1024, 1280, 1440, 1920 px. В браузере у `document.documentElement.scrollWidth` и `document.documentElement.clientWidth` должны быть одинаковые значения. На 390 px меню по умолчанию закрыто и раскрывается по кнопке, CTA выстраиваются вертикально.
