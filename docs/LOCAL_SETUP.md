# Рядом — локальный запуск и интеграция с backend

## Требования

- Node.js 22+ и npm.
- Для проверки Go backend: Docker + Docker Compose (либо Go и PostgreSQL).

## Быстрый запуск интерфейса без backend

Из корня репозитория:

```bash
cd frontend
npm install
cp -n .env.example .env.local
```

Убедитесь, что в `frontend/.env.local` выставлены следующие значения (добавьте или замените их):

```dotenv
HOME_API_MODE=demo
PSYCHO_API_MODE=demo
PSYCHO_API_BASE_URL=http://localhost:8080
```

Далее:

```bash
npm run dev -- -H 0.0.0.0 -p 3000
```

Откройте http://localhost:3000. На телефоне в той же Wi-Fi сети используйте `http://<IP_вашего_Mac>:3000` (при необходимости настройте `allowedDevOrigins` в `next.config.ts` под адрес локальной сети).

В этом режиме статьи, практики, встречи и роли используют демонстрационные данные. Демонстрационный SSO — не настоящая авторизация СПбГУ. Не используйте его для реальных пользователей.

## Тестирование frontend

```bash
cd frontend
npm test
npm run test:coverage
npm run build
```

Команда `test:coverage` проверяет порог покрытия **только для перечисленных в `frontend/package.json` модулей**, не для всего приложения. Перед объединением PR важно отдельно проверить сборку и основные пользовательские сценарии в браузере.

## Подключение Go backend

Для браузера по локальному HTTP задайте `AUTH_COOKIE_SECURE=false` в
`backend/.env` перед запуском Compose. Для первого администратора добавьте туда
`AUTH_BOOTSTRAP_ADMIN_USERNAME` и `AUTH_BOOTSTRAP_ADMIN_PASSWORD`. Подробности
о настройке начального аккаунта и HTTPS есть в [README бэкенда](../backend/README.md).

В одном терминале из корня репозитория:

```bash
cd backend
docker compose up --build -d
```

Проверка:

```bash
curl http://localhost:8080/health
curl http://localhost:8080/api/v1/home
curl http://localhost:8080/api/v1/psychoeducation/materials
```

Чтобы главная получала данные из Go, уберите `HOME_API_MODE=demo` из
`frontend/.env.local` и задайте:

```dotenv
HOME_API_URL=http://localhost:8080
HOME_API_PATH=/api/v1/home
```

После перезапуска Next.js раздел «На сегодня» загружает рекомендацию и
карточку практики через `/api/home`. Пока источник событий не подключён,
Go возвращает `event: null`, и карточка события не отображается.

Чтобы подключить вход, управление ролями, стену и статьи, задайте в
`frontend/.env.local`:

```dotenv
AUTH_API_BASE_URL=http://localhost:8080
PSYCHO_API_MODE=backend
PSYCHO_API_BASE_URL=http://localhost:8080
```

Перезапустите `npm run dev` и откройте
[`http://localhost:3000/auth/sso`](http://localhost:3000/auth/sso). В режиме
`AUTH_API_BASE_URL` страница принимает логин и пароль существующего локального
аккаунта. Войдите первым администратором и назначьте нужные роли заранее
подготовленным учётным записям на странице `/admin/roles`.

Для проверки публикаций войдите под пользователем с ролью `student` и
отправьте запись на стену, затем одобрите её под `moderator`. Отправьте статью
под `consultant`, одобрите её под другим пользователем с ролью `reviewer` и
проверьте, что она появилась в `/psychoeducation`. Форма решения передаёт версию
из очереди, когда API её возвращает. Если за это время автор изменил статью,
обновите очередь и прочитайте новую версию перед повторной проверкой.

`AUTH_API_BASE_URL` задаётся в окружении сервера Next.js и содержит адрес Go
без пути. Next.js пересылает запросы и cookie с того же адреса, по которому
открыта страница. Для локального демо оставьте `AUTH_API_BASE_URL` пустым.
При включённом `AUTH_API_BASE_URL` раздел `/events` и напоминания студента на
главной читают встречи из Go. Консультант или психолог может назначить встречу
аккаунтам с ролью `student`. Студент видит только свои встречи и может отменить
собственное участие. Дата и время вводятся по Москве.

Практики используют отдельные демонстрационные маршруты. Для действий с
демо-ролями используйте режим без `AUTH_API_BASE_URL`. Подключение университетского
SSO согласуется отдельно. Контракт Go описан в
[`api/openapi.yaml`](../api/openapi.yaml).

## Данные, секреты и публикация

- Не коммитьте `frontend/.env.local`, `.demo-data/`, `.next/`, `node_modules/` и любые пользовательские данные.
- Используйте `.env.example` только для безопасных примерных настроек.
- Сырые документы для импорта материалов находятся в `docs/content-import/`; импортированные начальные данные и миграции уже присутствуют в коде.
- Не подключайте настоящий SSO или production-доступы к демо-формам.
